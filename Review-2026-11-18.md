# Review 2026-11-18

Twelve reviews of the whole code base at `1e15b03`, the day after the review of
2026-11-17 was settled (`docs/history/Review-2026-11-17.md`). One topic each: memory,
performance, the hot path, robustness, untrusted input, promise against code, tests,
workarounds and maintainability, the changes of 2026-11-17, the Wayland protocol, key and
mouse encoding, fonts and rendering. Points settled in `docs/history`, CAVEATS.md or TODO
are left out. Line numbers are those of `1e15b03`. Fixed so far: 1.1, 1.2, 1.3, 1.5, 1.7,
1.8, 1.12, 1.14 to 1.16, 2.2, 2.3, 5.2 to 5.4 and 7.3; 1.13 and 5.1 went to
CAVEATS.md. This file moves to `docs/history` once every point is decided.

**Reproduced** means seen by running something: the VT core through `vtdump` or a harness,
mwt under headless sway in Podman, xterm 407 in Podman, or a probe built against `font.c`.
**Read** means from the code only. **Checked** marks the points confirmed against the code
once more while writing this. The reviewer numbers in brackets show where two or more
found the same.

No memory corruption and no way to inject input from pty output was found. A stress run of
1000 seeds of 20000 operations each under ASan and UBSan found nothing. `make check`
passes.


## 1. Bugs

1. **Rows below a scroll region stay stale when scrolled back.** Reproduced, checked.
   `vt.c:270-282` `scroll_up`: with a region from row 0 to above the last row and the view
   scrolled back, `push_hist` moves the view, so the rows below the region move down on
   the display, but only the region is marked. A footer set with DECSTBM shows it. An
   oracle over random input found about 30 in 2000 runs; marking the rows below the region
   too gave none. The fix of `af4a591` was incomplete. [9]
2. **Without a pidfd, a shell reaped by SIGCHLD set to ignore is never seen to end.**
   Reproduced, checked. mwt keeps the SIGCHLD disposition it was started with; with
   SIG_IGN the kernel reaps the shell, `waitpid` in the main loop (`mwt.c:2870`) gets
   ECHILD, and jobs holding the pty keep mwt for good. Fix: `signal(SIGCHLD, SIG_DFL)`, and
   ECHILD counts as gone. In the same place: after the main loop reaped the child,
   `reap_child` (`mwt.c:2710`) sends SIGHUP to a pid that may be reused. [4, 8, 9]
3. **Releasing Shift before the button ends a Shift drag in the wrong place.** Reproduced.
   `mwt.c:2234, 2261`: `mouse_mode()` is asked at press and at release separately. With
   Shift let go first, the release goes to the program, which never saw the press, the
   selection is not copied and `sel.dragging` stays on. Fix: note at the press who owns
   the button. [4]
4. **A double click on the right half of a wide character selects nothing.** Read, checked.
   `mwt.c:390` `cell_class` counts the WDUMMY half (cp 0) as blank. [7]
5. **REP repeats a character whatever came between.** Reproduced against xterm 407,
   checked. `vt.c:611, 1122`: `lastcp` is cleared only by RIS, so `a CR ESC[3b` writes
   `aaa`; xterm repeats only a graphic character just before. REP also drops DEC graphics
   (`ESC(0 q ESC[3b`), which only DECRQCRA sees. [3, 6]
6. **BEL does nothing**, though `mwt.info:8` declares `bel`. Checked: `mwt.c:2789` sets no
   `.bell`. `make terminfo` passes because `terminfo.py` counts the VT core's callback.
   Either a bell (urgency through xdg-activation, or a flash) or a line in CAVEATS. [6]
7. **The pty starts without IUTF8.** Read, checked. `mwt.c:2603` `forkpty` with the
   kernel's defaults: in canonical mode Backspace after ä or € erases one byte. [11]
8. **mwt.info lacks the modified keys vt.c sends.** Reproduced with ncurses: kUP3 to 7,
   kDN, kLFT, kRIT, kHOM, kEND, kDC, kPRV, kNXT 3 to 7 and kf25 to kf63 are missing, so
   ncurses programs with `keypad()` (htop, tig, neomutt, dialog) get Ctrl+Left and the like
   as stray characters. [11]
9. **A style in the font spec turns off the real bold and italic faces.** Reproduced.
   `font.c:150-157`: with `-f "DejaVu Sans Mono:style=Book"` FC_STYLE outranks weight and
   slant, and all four styles come from the regular file. [12]
10. **Fallback from a style face ignores the style asked for.** Reproduced. `font.c:293-310`
    returns any style face that has the character: U+27BF, only in DejaVu's bold file, comes
    out bold in regular, and double bold in bold italic. From `1642155`. [9]
11. **The cursor vanishes on reverse cells.** Read. `mwt.c:1120-1158`: the cursor colour
    defaults to the foreground, which is the background of a reverse cell, so block, bar,
    underline and hollow cursor disappear on status lines and highlights. The cursor cell
    also skips the minimum contrast. [12]
12. **DECALN keeps origin mode; DECSCUSR takes 7 and up as a bar; DECSTR keeps the cursor
    style.** Reproduced against xterm 407. `vt.c:686-694, 1012-1016, 400`. `is2` holds
    DECSTR, so `tput init` does not reset a bar vim left. [6]
13. **The synthesized release on a lost pointer can run a menu item.** Read. `mwt.c:2366`
    goes through `menu_button`, so pressing on Paste as the mouse drops off the seat pastes.
    From `34ceae7`. [9]
14. **X10: a release past column 223 is dropped after its press was sent.** Read.
    `mwt.c:2119`; the program thinks the button is held. [11]
15. **Shift+wheel in the alternate screen sends arrow keys while a program has the mouse.**
    Read. `mwt.c:2277-2285`. [11]
16. **Shift on the keypad with NumLock is used though xkb consumed it.** Read. Shift+KP_0
    pastes, Shift+KP_7 and KP_1 jump the history. `mwt.c:1898-1930`. [11]


## 2. Out of memory and hostile output

1. **The glyph cache hash can be flooded.** Reproduced. `font.c:391`: the low bits of the
   product depend only on the key's low bits, so about 200 KB of chosen code points build
   one cluster of 64k entries, and the lookups of one 200x55 frame take 631 ms instead of
   0.1 ms. Using the upper bits alone does not stop it; a random odd multiplier per process
   with multiply-shift, or a cap on probe length, does. The TODO entry on the hash
   underrates this. [5]
2. **REP in insert mode stalls a read.** Reproduced. `vt.c:1122` with `put()` at `vt.c:593`:
   `ESC[4h ESC[H x ESC[65535b` takes 753 ms per 4 KB read at 480x135, 1.6 s at 1000x300.
   The cap at a screenful does not help on large grids. Fix: REP of a width 1 character a
   row at a time, as ICH, or a cell budget per write. Whole screen operations (DECALN, SU
   or ED with a background) cost 26 to 60 ms a read at 480x135, as in xterm. [5]
3. **`close_range` has no fallback.** Read. `mwt.c:2621`: before Linux 5.9 or under seccomp
   it fails, unchecked, and the fds reach the shell again; before glibc 2.34 the build
   breaks. [5, 9]
4. **One failed FcFontSort is final.** Reproduced. `font.c:257-269` sets `sorted_tried`
   first, so after one failure every later fallback glyph is blank until a zoom. A glyph
   whose bitmap could not be allocated stays cached empty. [1]
5. **A synthesized style face has index 0.** Read. `font.c:169-177` copies regular's path
   but not its index, which the path and index check of `find_fallback` then misreads in a
   `.ttc`. [1, 8]
6. **Unchecked constructors left in `load_cursor_theme`** (`mwt.c:1717, 1730`), and
   `copy_clipboard` and `copy_primary` destroy the old source before the new one exists
   (`mwt.c:563-591`), which out of memory empties the clipboard. [1]


## 3. Performance

Measured with `make profile` and `tests/profbench.c`, 200x55 at 1080p, unless said.

1. **The pty is read in crumbs.** `mwt.c:2650-2669`: `yes` gives 16 B a read, `read()` is
   41 to 46 % of CPU. A 100 µs pause after a short read: `yes` 7.89 to 3.90 s CPU, `seq`
   2.28 to 1.30 s; `seq` ends 17 % later, to be tuned. [2]
2. **After a frame callback mwt parses up to 16 ms before it draws** (`mwt.c:2839-2885`).
   Drawing first: `yes` 46 to 62 frames/s, Ctrl+C in a flood 33 to 23 ms on average. [2]
3. **Content written again unchanged is drawn again**: the same screen at 60 Hz costs as
   much as new content (2.72 against 2.92 ms a frame). A copy per row and a `memcmp`. [2]
4. **Every left click redraws the window** (`mwt.c:2243, 2259`, also `sel_clear`,
   `select_all`); the limit of `1642155` covers drags only. [2]
5. **Commits with nothing new**: a title at 60 Hz gives 60 commits a second without damage.
   [2]
6. **CSI parameters go through `feed()` byte by byte**: a loop for digits gives `cup` and
   `sgr` +32 %. **`wcwidth` for every code point from U+0300**: a table for the BMP gives
   CJK +22 %. **DEC graphics bypass the fast path**: 12.6 against 2.0 ns a byte for ncurses
   borders. Each with identical state dumps before and after. [3]
7. Minor: `draw_row` works out colours for blank cells and evicts `readable()`'s one entry
   cache between words; `drop_paste_for_signal` calls `tcgetattr` for every typed key. [2, 3]


## 4. Wayland protocol

No request was found that a compositor would answer with a protocol error in normal use.

1. **A configure on a hidden surface is acked but not committed** until the frame callback
   comes, which hidden surfaces do not get (`mwt.c:2841`). Compositors that wait for that
   commit stall. [10]
2. **The wheel is decided per event, not per `wl_pointer.frame`**, and the axis source is
   never kept (`mwt.c:2295-2336`). Compositors that send partial axis events before the
   discrete one (mutter, KWin) scroll about two steps a notch. [10]
3. **`kb_leave` keeps the modifiers** (`mwt.c:2033-2047`), against the spec: Shift let go
   elsewhere still counts. [10]
4. **No min size, `configure_bounds` ignored**, so a window can commit larger than an
   interactive resize allows. **No scale before wl_compositor 6**: blurry on HiDPI where
   only v4 or v5 is offered. **`-T` and `-a` unbounded**: past 64 KiB the wire size field
   wraps. **`global_remove` only for the seat.** **A close during startup is lost**
   (`mwt.c:2837`). [4, 10]


## 5. Keys and mouse

Against xterm 407 and its ctlseqs; what matches is listed by the reviewer.

1. `ctrl_latin` maps letters only, so on Russian and similar layouts Ctrl+[ and Ctrl+] send
   the Cyrillic letter (`mwt.c:1828-1851`).
2. Ctrl+? sends `?`, xterm DEL (`mwt.c:1971`).
3. Mouse buttons 8 to 11 and the horizontal wheel are not reported (`mwt.c:2215, 2298`).
4. KP_Begin, Menu and F13 to F24 send nothing (`mwt.c:1853-1875`). [11]


## 6. Fonts and rendering

Measured with DejaVu Sans Mono, Noto Sans Mono, Noto Mono and D2Coding, 4 to 20 pt,
scales 1 to 4.

1. **Glyphs are clipped to their own cell**: synthesized italic loses up to 7 px at 2x,
   DejaVu's real oblique up to 5 px, synthesized bold its edges (`mwt.c:1137`). Clipping to
   the row would do, as rows are drawn whole.
2. **Fallback glyphs are not fitted to the cell**: ① from NanumGothic is 14 px in a 9 px
   cell; wide emoji sit left.
3. **Box drawing leaves gaps with Noto Sans Mono** (│ and █ 1 to 3 px short), so tmux
   borders and htop meters look dashed. Drawn by code, as foot and kitty do, or stretched.
4. **The cell width comes from another load mode than the glyphs** (`font.c:182-190`):
   DejaVu 11 pt at 2x gives 17 px cells for glyphs 18 px wide; accents and cedillas lose
   rows at 2x.
5. **The underline reaches into the next row** at 4 and 5 pt on HiDPI (`mwt.c:1143`), and
   stays there when only its row is redrawn.
6. **The FcFontSort order of `1642155` picks other faces for 20061 of 73510 fallback code
   points**: CJK now from NanumGothic (proportional) instead of D2Coding, symbols from Noto
   Symbols 2 instead of Symbola. The boxes fit; it is a change, not clearly worse.
7. An unknown family gives a proportional font silently; only FC_PIXEL_SIZE is set, so the
   optical size is chosen at 75 dpi. [12]

## 8. Tests

31 mutants of `vt.c` were run against `test_vt`, `fuzz_regress`, the replay sums and
`terminfo.py`. The fixes of 2026-11-17 for LNM, titles, the checksum and the parameter limit
fail their tests when taken out; the wrap flag fix only in part. These survived everything:

1. The wrap flag after ESC D, E, M, H and Z.
2. `vt_resize` on the alternate screen and with the view scrolled back.
3. SGR 22 clearing dim, `4:0`, SGR 25, the skip of unknown sub-parameters.
4. CNL and CPL clamped at the region, mode 1048, the DECRQM answer for mode 6.

Also without a test: the paths of `vt_abs_line` out of range; word separators, a backward
drag and trailing blanks in a selection; paste line ends byte for byte. Weak:
`evil.sh no_pidfd` only checks that mwt ends, not that it lives until the shell does;
`zoom_limit` checks a missing message, not that mwt still draws; `paste_queue_limit` only
the message. `vtdump` prints `MODE_ORIGIN`, which nothing sets (origin mode is
`c.origin`), so `terminfo.py` and the state comparisons do not see DECOM (checked), and
`vtdump` is built without `-fno-sanitize-recover` (`Makefile:119`). [7, 8]


## 9. Workarounds and maintainability

1. `tests/headless.sh`, used by keys, pixel, mouse, keyboard and leaks, still has the race
   that `tests/lib.sh` fixed: it sleeps 0.3 s for the IPC socket. esctest.sh and
   profile-run.sh too.
2. The harness copies left: the environment and the sway.conf in run.sh, evil.sh and
   width.sh, three ways of reading the screen, four walks of sway's tree, `wait_mwt` beside
   `wait_window`, the trap in evil.sh not killing vinput. The tests hard code the padding
   and the window position (`22`, `- 4`, `PAD = 2`).
3. Fixed sleeps beyond TODO's list: run.sh's waits after `seq 6000` and resizes,
   `stop_mwt`'s kill -9 after 0.3 s (a hang on SIGTERM goes unseen), `exit_with_jobs`.
4. `read_paste` drops at 64 MiB minus 4 KiB, CAVEATS says over 64 MiB; "64 MiB" is spelled
   out in three messages.
5. The zoom check of `34ceae7` copies `snap_size` and is skipped on a scale change, so a
   large floating window moved to a higher scale can still stop drawing.
6. Unnamed: `read_pty`'s 16 ms and 1 MiB, the 250 ms against 20 ms of the two pidfd
   fallbacks, the 2 s SIGHUP grace, the repeat defaults, the cursor sizes.
7. Makefile: pkg-config flags and `-std` are appended to CFLAGS, so `make CFLAGS=...` loses
   them (container-run.sh works around it); the sanitizer flags are copied eight times;
   the protocol headers do not depend on their XML.
8. `put_ascii` repeats the tail of `put()`; the origin row is computed twice. [8]
